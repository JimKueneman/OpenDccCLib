Detailed Description

Task orchestrator for Address-Only mode CV programming (S-9.2.3 §E).

Sequences address-only mode primitive operations to implement read (iterate address_verify 0-127) and write (write + verify) of CV#1. The decoder automatically clears CV#29 bit 5 and CV#19 when CV#1 is written — the command station does not need to handle these side effects explicitly. Singleton — only one service track per command station.

Read CV#1 (short address) using address-only mode. Iterates address_verify 0-127 until ACK.

Parameters
on_completedcc_service_mode_task_on_complete_callback_t called when complete: SUCCESS with the address found (0-127); ERROR (value 0) if no address 0-127 was ACKed.
on_progressdcc_service_mode_task_on_progress_callback_t called after each scan step (nullable); estimated_steps is reported as 0.
Returns
true if started, false if another operation is running.

Algorithm:

  1. Reject if another operation is in progress (state not IDLE)
  2. Load the context: scan value 0, cleared step count, callbacks
  3. Enter READ and issue address_verify for address 0 (a refused start puts the task back to IDLE and returns false)
  4. The scan continues from DccServiceModeTaskAddress_on_primitive_complete()
* @param on_complete Called when complete: SUCCESS with the address found (0-127), or ERROR if no address was ACKed.
* @param on_progress Called after each scan step (nullable).

Notify the task module that the primitive has finished its full operation (including recovery packets). Wire this into the primitive's on_complete slot via dcc_config.c. The task module advances its state machine on this event; the ACK outcome is taken from result (SUCCESS = ACK detected by the common module's pulse-width measurement, anything else = no ACK).

Parameters
resultdcc_service_mode_result_enum of the primitive operation (passed through from primitive callback).

Notify the task module that the primitive has finished its full operation (including recovery packets). Wire this into the primitive's on_complete slot via dcc_config.c. The task module advances its state machine on this event; the ACK outcome is taken from result (SUCCESS = ACK detected by the common module's pulse-width measurement, anything else = no ACK).

Algorithm:

  1. Record the ACK outcome: SUCCESS from the primitive means a valid ACK was measured, anything else means no ACK
  2. Dispatch on the current state: the three scanning states share advance_scan(), the others go to their _advance* handler
  3. Ignore the event when IDLE (no operation in progress)
* @param result Result of the primitive operation (passed through from primitive callback).
*
