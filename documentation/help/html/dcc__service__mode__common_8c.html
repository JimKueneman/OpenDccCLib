◆ DCC_ACK_MIN_SAMPLES

#define DCC_ACK_MIN_SAMPLES    ((USER_DEFINED_DCC_ACK_MIN_DURATION_US / DCC_ONE_BIT_HALF_PERIOD_US) - 1)

Minimum length of an elevated-current span, in ack_sample ticks, for a valid ACK.

One less than the tick count of USER_DEFINED_DCC_ACK_MIN_DURATION_US so a span that is exactly the minimum duration still qualifies. With the typical config this is 85 samples (~4930 us).

◆ DCC_ACK_MAX_SAMPLES

#define DCC_ACK_MAX_SAMPLES    (USER_DEFINED_DCC_ACK_MAX_DURATION_US / DCC_ONE_BIT_HALF_PERIOD_US)

Maximum consecutive high samples for a valid ACK.

S-9.2.3 p.2 defines a Basic ACK as >= 60 mA sustained for 6 ms +/- 1 ms (a two-sided 5-7 ms window). A high run that lasts longer than the upper bound is treated by S-9.2.3 p.3 as an over-current / fault condition, NOT an ACK. We therefore reject any run exceeding this many samples. Unlike DCC_ACK_MIN_SAMPLES (which subtracts 1), the MAX uses the raw quotient as the inclusive upper bound. With the typical config: MIN ~= 85, MAX ~= 120.

◆ USER_DEFINED_DCC_ACK_DROPOUT_TOLERANCE_US

◆ DCC_ACK_DROPOUT_SAMPLES

#define DCC_ACK_DROPOUT_SAMPLES    (USER_DEFINED_DCC_ACK_DROPOUT_TOLERANCE_US / DCC_ONE_BIT_HALF_PERIOD_US)

Dropout tolerance: bridge brief sub-threshold dips during an ACK.

A real Basic ACK is the decoder pulsing a noisy load (motor): commutation/PWM ripple can make the current-sense comparator chatter below threshold for a sample or two mid-pulse. We bridge up to this many CONSECUTIVE low samples into the run rather than ending it, so a noisy 6 ms ACK is still measured as one ~6 ms span. A low run longer than this is a real falling edge and closes the span.

◆ DccServiceModeCommon_ack_sample()

void DccServiceModeCommon_ack_sample ( dcc_service_mode_common_context_t * context,
uint16_t sense_value )

Sample the current sense input from the timer ISR.

Algorithm:

  1. Return once an ACK has already been latched for this operation
  2. Return unless the state is COMMAND or RECOVERY
  3. Return while the ACK window is blanked (S-9.2.3 line 55: the first DCC_SERVICE_MODE_ACK_BLANK_PACKETS command packets mask the decoder mode-switch transient)
  4. Reading >= USER_DEFINED_DCC_ACK_THRESHOLD_MA: extend the span (_ack_sample_elevated)
  5. Reading below threshold inside a span: treat as a dropout (_ack_sample_dropout); below threshold with no span open: ignore
* @param context Pointer to dcc_service_mode_common_context_t instance.
* @param sense_value Raw reading from current sense hardware.
*

◆ DccServiceModeCommon_run()

void DccServiceModeCommon_run ( dcc_service_mode_common_context_t * context)

Main loop processing for service mode state machine.

Algorithm:

  1. Return unless service mode is active
  2. If a packet has been loaded, return until the ISR has flagged it complete, then clear both flags
  3. Return unless the encoder reports idle (belt-and-suspenders)
  4. RESET_PRE: load a reset packet until DCC_SERVICE_MODE_RESET_PRE_COUNT have been sent, then clear the ACK detector state and enter COMMAND
  5. COMMAND, RECOVERY, RESET_POST: delegate to the per-state helper
* @param context Pointer to dcc_service_mode_common_context_t instance.
*

◆ DccServiceModeCommon_begin_operation()

bool DccServiceModeCommon_begin_operation ( dcc_service_mode_common_context_t * context,
const dcc_packet_t * command_packet,
dcc_service_mode_step_callback_t on_step_complete,
bool is_write_operation,
uint8_t command_repeat,
uint8_t recovery_count )

Start a single service mode operation.

Algorithm:

  1. Refuse (return false) when service mode is not active
  2. Refuse (return false) when the state is not IDLE
  3. Copy the command packet into the context and latch the callback, write flag, repeat and recovery counts
  4. Reset the counters, the ACK detector (window closed, no span) and the result to NO_ACK
  5. Enter RESET_PRE; DccServiceModeCommon_run() sends the packets from here on
* @param context Pointer to dcc_service_mode_common_context_t instance.
* @param command_packet Pointer to dcc_packet_t to send during the command phase.
* @param on_step_complete Callback fired when the operation completes (dcc_service_mode_step_callback_t).
* @param is_write_operation true for write operations (adds the recovery phase), false for verify.
* @param command_repeat Number of command packets to send.
* @param recovery_count Number of recovery packets to send after the command phase (writes only).
*
Returns
true if the operation started, false if service mode is not active or an operation is already in progress.
