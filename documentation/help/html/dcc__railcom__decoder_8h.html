Detailed Description

RailCom decoder-side transmit engine.

Recognizes a DCC command addressed to this decoder before its XOR byte, arms the ADR (Channel 1) reply plus the app's optional Channel 2 reply, and – at the packet end-bit edge – bit-bangs the 4/8-encoded response into the RailCom cutout (S-9.3.2 sec 2.4) via the interface's tx_pin_set, timed off the app's delay_us and bracketed by the shared-resource lock + edge-IRQ mask. Disabled if tx_pin_set is NULL. Timing: 4 us per bit (DCC_RAILCOM_TX_BIT_US), 80 us blank from the end-bit edge to Channel 1 (DCC_RAILCOM_TX_BLANK_US), 33 us gap between the channels (DCC_RAILCOM_TX_GAP_US). Only a multifunction packet addressed to this decoder whose length the recognizer can size gets a reply.

void DccRailcomDecoder_transmit ( const uint8_t * data,
uint8_t count )
extern

Transmit the armed RailCom reply into the cutout (call at the packet end-bit edge, from the bit decoder's on_packet_received).

No-op unless a command addressed to this decoder was recognized while its bytes arrived (see DccRailcomDecoder_on_byte_received). Re-validates the XOR of the complete packet, and only then bit-bangs ADR (Channel 1) plus the app's optional Channel 2 reply – blank, Ch1, gap, Ch2 – timed off the end-bit edge per S-9.3.2 sec 2.4. Blocks with interrupts masked for the whole reply (80 us blank, two Channel 1 bytes, 33 us gap, then any Channel 2 bytes at 40 us per byte); intended for ISR context. Sends nothing when tx_pin_set or delay_us is NULL.

Parameters
dataComplete packet bytes including the trailing XOR byte.
countNumber of bytes in data.

Transmit the armed RailCom reply into the cutout (call at the packet end-bit edge, from the bit decoder's on_packet_received).

Algorithm:

  1. Return unless a command addressed to this decoder was armed before its XOR.
  2. Disarm (one reply per packet, whatever the outcome).
  3. Validate the complete packet's XOR; on failure send nothing.
  4. Bit-bang the pending Channel 1 (ADR) and any Channel 2 bytes.
* @param data  Complete packet bytes including the trailing XOR byte.
* @param count Number of bytes in data.

uint8_t DccRailcomDecoder_packet_length ( const uint8_t * data,
uint8_t count )
extern

Total DCC packet length (including the XOR byte) implied by the bytes received so far, from the self-describing multifunction-decoder instruction format (S-9.2.1).

Pure – no side effects, no module state. The decoder-side RailCom recognizer uses it to know a command is complete (the next byte is the XOR) before the cutout. Returns 0 when the length cannot yet be determined: too few bytes to classify, an extended form not yet sized (XPOM), an accessory/reserved leading byte, or an instruction this module does not size.

Parameters
dataPacket bytes received so far (address + instruction).
countNumber of bytes in data.
Returns
Total packet length in bytes including XOR, or 0 if undeterminable.

Total DCC packet length (including the XOR byte) implied by the bytes received so far, from the self-describing multifunction-decoder instruction format (S-9.2.1).

Algorithm:

  1. Size the address from byte 0 (1 or 2 bytes); 0 if not a multifunction packet.
  2. Once the opcode byte is present, size the instruction from it.
  3. Total = address bytes + instruction bytes + 1 (XOR). Returns 0 while still undeterminable, or for an extended form (XPOM) whose length is not yet grounded.
* @param data  Packet bytes received so far.
* @param count Number of bytes in data.
*
Returns
Total packet length including XOR, or 0 if undeterminable.

Extract the multifunction address and its type from a packet's leading bytes.

Pure – no side effects, no module state. Decodes the broadcast, short (CV1), long (CV17/18), and idle leading bytes. The recognizer compares the result against this decoder's own address to decide "addressed to me."

Parameters
dataPacket bytes received so far.
countNumber of bytes in data.
addressOut: decoded dcc_address_t (valid only when true is returned).
typeOut: decoded dcc_address_type_enum (valid only when true returned).
Returns
true if an address was decoded; false if too few bytes or an accessory/reserved leading byte (not a multifunction packet).

Algorithm:

  1. Size the address (1 or 2 bytes); reject accessory/reserved/short-of-bytes.
  2. Broadcast (0x00) and idle (0xFF) decode to their own types.
  3. 1-byte form is a short address; 2-byte form is a 14-bit long address.
* @param data    Packet bytes received so far.
* @param count   Number of bytes in data.
* @param address Out: decoded address.
* @param type    Out: decoded address type.
*
Returns
true if an address was decoded; false otherwise.

◆ DccRailcomDecoder_on_byte_received()

void DccRailcomDecoder_on_byte_received ( const uint8_t * data,
uint8_t count )
extern

Feed one assembled packet byte to the RailCom Tx recognizer.

Wired (in dcc_config) to the bit decoder's on_byte_received. As bytes arrive it recognizes a complete command addressed to this decoder (the next byte is the XOR) and arms the ADR reply plus the app's optional Channel 2 reply (firing on_railcom_request before the XOR). The transmit itself happens later, at the end-bit edge, in DccRailcomDecoder_transmit. Only a multifunction packet whose length this module can size (see DccRailcomDecoder_packet_length) and whose address matches the one set by DccRailcomDecoder_set_address arms a reply; accessory, unsized and foreign packets are ignored.

Parameters
dataPacket bytes assembled so far.
countNumber of bytes in data.

Algorithm:

  1. At count 1 (a new packet) drop any stale armed state.
  2. If already armed for this packet, wait for the end-bit edge.
  3. Size the packet from the bytes so far; continue only when the length is exactly count + 1 (the next byte is the XOR). Unsized, accessory and incomplete packets never arm.
  4. Decode the address; if it matches the cached decoder address and type, fill Channel 1 (ADR), ask the app for Channel 2 through on_railcom_request (edge-ISR path) and arm the reply.
* @param data  Packet bytes assembled so far.
* @param count Number of bytes in data.
*
